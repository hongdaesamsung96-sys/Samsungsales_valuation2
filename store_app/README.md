# 매장 상권/고객/세일즈톡 분석 앱 (프로토타입)

삼성전자판매 전국 매장을 위한 매장별 상권 분석 + 고객 세그먼트 + 세일즈톡 반응 로그 시스템의
동작하는 프로토타입이다. 역할 기반 로그인으로 화면이 둘로 나뉜다.

- **상담사용 화면**: 세일즈톡 참고자료(세그먼트별 추천상품/타이밍/멘트) 열람 + 로그 입력만 가능.
  상권분석/통계 등 "데이터 분석 내역"은 볼 수 없음.
- **본사/지사 관리자용 화면**: 상권분석, 고객 세그먼트 분포, 세일즈톡 로그 열람, 통계, (본사만) 지사별
  비교까지 조회 가능. 지사 관리자는 자기 지사 산하 매장만, 본사 관리자는 전국 매장을 볼 수 있음.

이 권한 분리는 화면 UI 차원의 안내가 아니라 서버(`server/sync_server.py`)가 로그인 토큰의 역할/범위를
검사해 강제한다 — 상담사 계정으로 관리자 API를 호출하면 403이 반환된다.

매장은 매장명/위치로만 구분하고 "오피스형/주거형" 같은 유형 라벨은 두지 않는다. 어떤 연령대·성별·거주
형태 고객이 많이 오는 매장인지는 상권분석 화면에서 상담로그(연령대/성별/거주지 태그)를 집계해 실측으로
보여준다 - 매장에 미리 붙여둔 가정이 아니라 쌓인 데이터가 알려주는 방식이다.

## 동료들과 URL로 공유하려면 (중간보고용)

`server/sync_server.py`가 프론트엔드(web/)와 API를 한 프로세스에서 같이 서빙하도록 만들어져 있어서,
이 서버 하나만 무료 호스팅(Render 등)에 올리면 `https://xxx.onrender.com` 형태의 URL 하나로 로그인부터
전체 화면까지 다 열린다. 단계별 절차(코딩 지식 불필요, 5분 내외)는 `docs/웹앱_배포_가이드.md` 참고.

## 폴더 구조

```
store_app/
├── data/
│   ├── gen_db.py          # 샘플 DB 생성 스크립트 (SQLite + JSON export)
│   ├── store_analysis.db  # SQLite DB (지사 4곳, 매장 10곳, 고객 200명, 상담로그 300건)
│   └── store_data.json    # 서버가 읽는 전체 데이터 (앱에는 절대 번들하지 않음 - 아래 보안 참고)
├── web/                   # 실제 앱 프론트엔드 (순수 HTML/CSS/JS, 태블릿용)
│   ├── index.html         # 로그인 화면 + 상담사 화면 + 관리자 화면 (역할별 분기)
│   ├── css/style.css
│   ├── js/app.js          # 로그인/토큰관리/역할별 화면 렌더링 로직
│   ├── js/config.js       # 서버 주소 설정 (배포 시 이 파일만 수정)
│   ├── manifest.json      # PWA 설치 설정
│   ├── service-worker.js  # 오프라인 캐싱 (비민감 참고자료만 캐시)
│   ├── icons/
│   └── data/public_reference.json  # 세그먼트/스크립트 등 "비민감" 참고자료만 (오프라인 폴백용)
├── server/
│   └── sync_server.py     # API + 정적 웹서빙을 한 프로세스에서 처리 (역할 기반 접근제어 포함)
├── docs/
│   ├── 웹앱_배포_가이드.md            # URL로 배포해서 동료들과 공유하는 방법 (중간보고용)
│   ├── APK_빌드_가이드.md            # 실제 .apk로 빌드하는 전체 절차
│   └── AI_상담로그_파이프라인_설계.md  # 녹음→AI분석→로그 자동화 설계 + 접근권한/법적 고려사항
├── render.yaml             # Render.com 배포 설정 (Blueprint)
├── capacitor.config.json  # Capacitor 설정 (APK 빌드용)
└── package.json           # npm 의존성 정의 (Capacitor)
```

**보안 참고**: 이전 버전은 전체 데이터(`store_data.json`)를 앱에 그대로 번들해 오프라인에서도 볼 수
있게 했었는데, 이러면 APK를 풀어보면 상담사 권한으로도 전체 매장 데이터를 볼 수 있게 돼 "분석 내역은
관리자만" 정책이 무력화된다. 그래서 앱에는 세그먼트/스크립트 같은 비민감 참고자료(`public_reference.json`)
만 번들하고, 나머지는 반드시 로그인 후 서버에서 역할에 맞게 필터링된 데이터만 받아오도록 바꿨다.

## 지금 바로 로컬에서 확인해보는 방법

1. `cd server && python3 sync_server.py` (기본 포트 8787) - 이 서버 하나가 화면과 API를 모두 서빙한다
2. 브라우저에서 `http://localhost:8787` 접속
3. 데모 계정으로 로그인해서 화면 차이 확인 (비밀번호 전부 `pass1234`)

`web/js/config.js`의 `STORE_APP_API_BASE`는 빈 문자열(같은 서버) 상태 그대로 두면 된다. 프론트엔드와
API를 다른 서버로 분리해서 띄우고 싶을 때만 이 값을 실제 API 서버 주소로 바꾸면 된다.

| 계정 | 역할 | 볼 수 있는 것 |
|---|---|---|
| `staff_gangnam` | 강남본점 상담사 | 세일즈톡 참고자료 + 로그 입력 |
| `staff_haeundae` | 해운대점 상담사 | 위와 동일 (해운대점) |
| `branch_sudokwon` | 수도권지사 관리자 | 수도권지사 산하 7개 매장 분석 데이터 |
| `branch_youngnam` | 영남지사 관리자 | 영남지사 산하 매장 분석 데이터 |
| `hq_admin` | 본사 관리자 | 전국 전체 + 지사별 비교 |

태블릿/휴대폰 브라우저로 접속 후 "홈 화면에 추가"하면 앱처럼 아이콘 설치됨.

## 실제 .apk로 만들려면

`docs/APK_빌드_가이드.md` 참고. 이 세션은 네트워크 제한으로 Android SDK/npm 패키지를 직접 받을 수 없어,
인터넷이 되는 개발 PC에서 `npm install` → `npx cap add android` → `gradlew assembleRelease` 순서로
진행하면 된다. 앱 로직 자체는 이미 완성돼 있어 빌드만 하면 됨.
