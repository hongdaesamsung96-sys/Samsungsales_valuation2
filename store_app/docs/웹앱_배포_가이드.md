# 웹앱을 URL로 공유하는 방법 (중간보고용)

이 앱은 프론트엔드(웹앱)와 백엔드(로그인/데이터 API)가 `server/sync_server.py` 한 프로세스에서 함께
서빙되도록 만들어져 있다. 즉 이 서버 하나만 어딘가에 띄우면 `https://xxx.onrender.com` 같은 URL 하나로
로그인 화면부터 상담사/관리자 화면까지 전부 열린다.

**왜 지금 이 세션에서 바로 URL을 못 만들어 주냐면**: 이 작업환경은 보안상 외부 인터넷 접속이 극히 제한된
화이트리스트 방식이라, GitHub·PyPI·Render 같은 배포에 필요한 외부 서비스에 이 세션에서 직접 접속할 수
없다(테스트해보니 전부 `blocked-by-allowlist`로 막힘). 그래서 배포는 사람이 직접 몇 분만 클릭하면 되는
과정으로 아래에 정리했다. 코딩 지식 없이도 따라할 수 있다.

## 준비물

- GitHub 계정 (무료, 없으면 github.com에서 이메일로 1분 내 가입)
- Render 계정 (무료, 카드 등록 불필요, GitHub 계정으로 바로 로그인 가능)

## 1단계: GitHub에 코드 올리기 (git 명령어 없이, 웹에서 클릭만)

1. github.com 로그인 → 우측 상단 **+** → **New repository**
2. 저장소 이름 입력 (예: `store-app-demo`), **반드시 Private 선택** (Public으로 하면 인터넷에 있는
   누구나 코드를 볼 수 있다 - 아래 "공개 범위" 절 참고) → **Create repository**
3. 저장소 페이지에서 **Add file → Upload files** 클릭
4. `store_app.zip`을 압축 풀면 나오는 `store_app` 폴더 안의 파일/폴더 전체(`data/`, `web/`, `server/`,
   `docs/`, `render.yaml`, `package.json`, `capacitor.config.json`, `README.md`)를 통째로 끌어다 놓기
   (브라우저 업로드는 폴더째로 드래그 가능)
5. 아래 **Commit changes** 클릭

## 2단계: Render에 배포하기 (클릭 몇 번)

1. render.com 접속 → GitHub 계정으로 로그인/가입
2. 대시보드에서 **New +** → **Blueprint**
3. 방금 만든 `store-app-demo` 저장소 선택 → Render가 저장소 안의 `render.yaml`을 자동으로 읽어서
   설정을 채워줌 (Python, 무료 플랜, 시작 명령어 등 이미 다 세팅되어 있음)
4. **Apply** 클릭 → 1~3분 정도 빌드/배포 진행
5. 완료되면 `https://store-app-demo-xxxx.onrender.com` 같은 URL이 발급됨 → 이 URL을 그대로 동료들에게
   공유하면 됨

## 공개 범위: 코드는 누가 볼 수 있고, 앱 URL은 누가 볼 수 있나

이 둘은 서로 다른 문제라 나눠서 봐야 한다.

**1) GitHub에 올린 코드/파일 - "Private" 저장소로 만들면 지정한 사람만 본다.**
저장소를 Private로 만들면 저장소 소유자와, **Settings → Collaborators** 에서 직접 초대한 사람만 코드를
볼 수 있다. 검색엔진에 노출되지도 않고, URL을 안다고 아무나 들어올 수도 없다. 무료 GitHub 계정도
Private 저장소에 협업자를 원하는 만큼 초대할 수 있다(추가 비용 없음). 반대로 Public으로 만들면 인터넷의
누구나 코드를 볼 수 있고 검색도 된다 - 그래서 위 1단계에서 Private를 선택하라고 한 것.

이 코드 안에 실제 고객 개인정보는 없다(전부 이 프로젝트에서 만든 가상의 샘플 데이터). 다만 데모 로그인
비밀번호(`pass1234`)가 코드에 그대로 박혀 있으니, Private 저장소 + 필요한 사람만 초대하는 걸 꼭 지키는
게 좋다.

**2) 배포된 앱 URL(`https://xxx.onrender.com`) - 이건 기본적으로 "링크를 아는 사람은 누구나" 접속 가능하다.**
GitHub 저장소를 Private로 해도, Render에 배포된 실제 서비스 URL은 별개다. 무료 플랜에는 접속을 제한하는
기능이 없어서, 이 URL을 아는 사람이면 로그인 화면까지는 누구나 들어올 수 있다(로그인 화면 다음부터는
아이디/비밀번호가 있어야 들어가지만, 데모 계정 비밀번호가 전부 `pass1234`로 동일해서 URL과 함께
비밀번호까지 알려지면 그 뒤로는 못 막는다). 완전히 못 들어오게(내부 전용) 하려면 Render 유료 플랜의
Private Service가 필요한데, 이러면 외부 URL 자체가 없어져서 "동료에게 링크 공유"라는 원래 목적과
안 맞는다.

그래서 이 서버에는 **한 겹 더 잠그는 옵션**을 넣어뒀다: Render 환경변수에 `SITE_ACCESS_USER`,
`SITE_ACCESS_PASS`를 채워두면, 화면이 뜨기도 전에 브라우저 기본 로그인창(비밀번호 입력창)이 한 번 더
뜬다. 이 아이디/비번을 모르면 로그인 화면조차 볼 수 없다. 이 값들은 앱 안의 계정(`staff_gangnam` 등)과
는 별개이니, 원하는 아이디/비번으로 아무거나 정하면 된다. 사용법: Render 대시보드 → 서비스 →
**Environment** 탭 → `SITE_ACCESS_USER`, `SITE_ACCESS_PASS` 값 입력 → 저장(자동 재배포).

정리하면: **코드 공개 범위**는 Private 저장소 + Collaborators 초대로 확실히 통제되고, **URL 접근 범위**는
기본적으로 "링크를 아는 사람 전부"이므로 `SITE_ACCESS_USER`/`PASS`를 설정해서 원하는 사람에게만 그
아이디/비번까지 같이 알려주는 방식으로 좁힐 수 있다.

## 로그인 계정 (동료들에게 같이 안내)

| 아이디 | 비밀번호 | 역할 |
|---|---|---|
| `staff_gangnam` | `pass1234` | 강남본점 상담사 화면 |
| `staff_haeundae` | `pass1234` | 해운대점 상담사 화면 |
| `branch_sudokwon` | `pass1234` | 수도권지사 관리자 화면 |
| `branch_youngnam` | `pass1234` | 영남지사 관리자 화면 |
| `hq_admin` | `pass1234` | 본사 관리자 화면 (전국 + 지사별 비교) |

## 알아두면 좋은 점 (중간보고용 데모 한정)

- **무료 플랜은 15분간 요청이 없으면 서버가 잠든다.** 그 상태에서 첫 접속하면 서버가 깨어나는 데
  20~50초 정도 걸릴 수 있다 (로딩이 오래 걸려 보여도 정상). 동료들에게 미리 안내해두면 좋다.
- **(중요) 위 "잠들었다 깨는" 과정 자체가 상담 로그를 초기화시킨다.** 재배포할 때만 그런 게 아니라,
  15분 유휴로 잠들었다가 다음 요청에 깨어날 때마다 디스크가 배포 시점 상태로 되돌아간다. 즉 데모 중
  로그를 입력해도 15분 넘게 아무도 안 들어오면 다음 접속 때 사라진다 - 이 문제를 없애려면 바로 아래
  "데이터가 계속 사라지지 않게 하려면" 항목대로 GitHub Gist 연동을 설정하면 된다.
- **이 URL은 데모용 계정과 시크릿으로 동작한다.** 실제 서비스로 전환할 때는
  `AI_상담로그_파이프라인_설계.md` 3-6절에 정리된 대로 SSO 연동, HTTPS(Render는 기본 제공), 별도
  운영 DB로 교체해야 한다.
- 링크를 지정한 사람 외에는 못 보게 하고 싶다면 위 "공개 범위" 절의 `SITE_ACCESS_USER`/`SITE_ACCESS_PASS`
  설정을 사용하면 된다.

## 데이터가 계속 사라지지 않게 하려면 (GitHub Gist 연동, 선택)

무료 플랜에서도 상담 로그가 사라지지 않게 하고 싶다면, Render의 로컬 디스크 대신 GitHub Gist를 저장소로
쓰도록 서버에 이미 만들어 놨다. 어차피 1단계에서 GitHub 계정을 쓰니 추가 서비스 가입 없이 5분이면 된다.

1. `data/store_data.json` 파일 내용을 전부 복사
2. gist.github.com 접속 → 로그인 → 파일명에 `store_data.json` 입력 → 내용 붙여넣기 → **Create secret gist**
   클릭

   주의: GitHub의 "secret gist"는 검색·목록에 안 뜬다는 뜻이지 진짜 비공개는 아니다 - Gist 주소(URL)를
   아는 사람은 GitHub 협업자가 아니어도 내용을 볼 수 있다. 주소가 무작위 문자열이라 추측되긴 어렵지만,
   Private 저장소처럼 "초대한 사람만" 볼 수 있는 건 아니라는 점은 알아두는 게 좋다. 이 Gist에는 실제
   고객 개인정보 없이 이 프로젝트의 샘플 데이터 + 상담사가 입력한 비식별 통계(연령대/성별/거주유형
   태그)만 쌓이니, 유출돼도 심각한 문제로 이어질 정보는 아니다.
3. 생성된 Gist 페이지 주소(`https://gist.github.com/아이디/xxxxxxxx`)에서 마지막 `xxxxxxxx` 부분이
   Gist ID
4. github.com → 우측 프로필 → **Settings** → **Developer settings** → **Personal access tokens** →
   **Tokens (classic)** → **Generate new token** → 권한(scope)에서 **gist**만 체크 → 생성 후 나오는
   토큰 문자열 복사 (이 화면 나가면 다시 못 봄, 꼭 복사)
5. Render 대시보드 → 방금 만든 서비스 → **Environment** 탭 → 환경변수 추가:
   - `GIST_ID` = 3번에서 확인한 값
   - `GITHUB_TOKEN` = 4번에서 복사한 토큰
6. 저장하면 자동으로 재배포되고, 이후부터는 상담사가 로그를 입력할 때마다 이 Gist에 저장되고, 서버가
   깨어날 때도 로컬 파일이 아니라 이 Gist에서 최신 데이터를 불러온다.

이렇게 안 하면(환경변수 안 채우면) 서버는 그냥 기존처럼 로컬 파일을 쓰고, 위에서 설명한 "깨어날 때마다
초기화"가 그대로 적용된다 - 처음 배포된 300건 샘플 데이터는 항상 그대로 보이니 UI/기능을 보여주는
용도로는 문제없고, 실제로 로그를 입력해서 그게 계속 쌓이는 걸 보여주고 싶을 때만 이 설정이 필요하다.

## 앱을 수정한 뒤 다시 배포하려면

`web/` 폴더 안의 파일을 고친 뒤, GitHub 저장소 페이지에서 해당 파일을 다시 업로드(덮어쓰기)하면 Render가
자동으로 감지해서 재배포한다 (Blueprint 연결 시 기본적으로 자동 배포가 켜져 있음).

## 대안: 다른 플랫폼을 쓰고 싶다면

Render 대신 Railway, Fly.io 같은 곳도 동일한 방식(Python 표준 라이브러리만 사용, `PORT` 환경변수 사용,
시작 명령어 `python3 server/sync_server.py`)으로 바로 배포된다. 회사에 이미 쓰는 클라우드 계정(AWS,
Naver Cloud 등)이 있다면 그쪽에 올려도 되고, 같은 서버 코드를 그대로 쓰면 된다.

## Netlify는 왜 추천하지 않나

Netlify는 기본적으로 정적 사이트 호스팅이라, 로그인·역할별 데이터 조회 같은 이 앱의 백엔드 로직은
"Netlify Functions"(서버리스 함수)로 옮겨야 한다. 문제는 서버리스 함수는 요청이 올 때마다 잠깐 떴다
사라지는 구조라, 지금 서버가 쓰는 방식(`data/store_data.json` 파일에 직접 읽고 쓰기, 커스텀 URL 라우팅)이
그대로 안 돌아간다 - 로그인 라우트/상담사 라우트/관리자 라우트를 함수 단위로 쪼개서 다시 짜야 하고,
상담 로그 저장도 파일 대신 외부 DB(Netlify Blobs, FaunaDB 등)로 바꿔야 한다. 지금 코드를 거의 새로
써야 하는 수준이라 중간보고 일정에는 맞지 않아서 권장하지 않았다.

## GitHub 없이 배포하고 싶다면 (Replit)

GitHub 계정을 만들기 싫은 거라면 **Replit**이 더 잘 맞는다. Render와 달리 Git 저장소 연결 없이 파일을
직접 올려서 바로 실행할 수 있고, 지금 서버 코드(파일 기반 저장, 커스텀 라우팅)를 고칠 필요도 없다.

1. replit.com 접속 → 이메일 또는 구글 계정으로 가입 (GitHub 불필요)
2. **Create Repl** → 언어는 **Python** 선택하지 말고 "Import from" 또는 업로드 옵션으로 `store_app.zip`
   또는 압축 푼 `store_app` 폴더를 업로드 (파일 패널에 드래그해서 넣어도 됨)
3. 우측 **Run** 버튼 클릭 시 실행 명령을 `python3 server/sync_server.py`로 지정 (`.replit` 설정 파일이나
   Run 버튼 옆 설정에서 지정 가능)
4. 실행되면 우측 프리뷰 창에 임시 URL이 뜨는데, 이건 Repl을 열어둔 동안만 유지된다. 계속 켜진 URL이
   필요하면 상단 **Deploy** 버튼으로 배포해야 영구 URL이 발급된다 (무료 플랜은 가동시간/성능에 제약이
   있을 수 있으니, 배포 화면에서 현재 요금제 조건을 확인해보는 게 좋다)

정리하면: **코드 그대로 + GitHub 없이** 빠르게 보여주고 싶다 → Replit. **정식 URL을 계속 운영하고 싶다** →
Render(GitHub 필요)가 더 안정적이다. Netlify는 지금 구조로는 적합하지 않다.
